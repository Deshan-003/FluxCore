# Performance prediction

Predictions are lightweight statistical estimates, not guaranteed future values. They use at most 30 minutes of local Phase 4 observations sampled every 15 seconds and are recalculated no more than once per minute. CPU, RAM, commit charge, adapter-scoped GPU/VRAM use and per-volume disk capacity/free bytes use separately identified series. Phase 2's existing memory pressure/exhaustion forecast remains authoritative for memory pressure. Disk capacity is only forecast where a real volume total/free counter exists. Process workload prediction is not implemented.

The engine requires a current metric, at least eight observations, two minutes of observation span, at least 75% metric coverage, and no observation gap greater than 90 seconds. Otherwise it returns an unavailable estimate with its data requirement. It evaluates recent walk-forward error for a rolling mean, time-adjusted exponential smoother and linear trend, then uses the least-error model for the requested lead. CPU/RAM/commit/GPU/VRAM-use/disk-capacity percentages are bounded to their meaningful 0–100 range; byte forecasts cannot be negative.

Each result returns target and observation timestamps, metric, selected method, horizon, sample count, span, coverage, actual target observation when available, estimated value and an **indicative** residual band. Confidence is low when the requested lead exceeds a quarter of the observation span, there are fewer than six validation points, coverage is below 90%, the error band is large, or a percentage estimate was clamped. Other eligible cases are labelled moderate. These are conservative product-quality labels, not statistically calibrated probabilities.

A saved prediction is scored only against an actual sample for the same metric within 30 seconds after its target. Out-of-window/missed targets are marked checked but are not reported as actual values. Do not infer prediction quality from synthetic data; the dashboard starts its comparison table as empty until real observations arrive. Existing Phase 1–3 history predates the Phase 4 metric identity and is deliberately not relabelled or backfilled.

The forecasting and error-selection algorithm has synthetic **unit tests only**; this is not production telemetry. No native forecast-accuracy benchmark across real workloads, ML model, seasonal analysis or calibrated confidence interval is claimed.
